# نظام الحقول الخاصة بالأقسام — دليل الاستخدام

## 🎯 الفكرة

بدل أن تكون الاختصاصات مبرمجة بشكل ثابت في الكود، أصبح بإمكانك **تعريف أي حقل لأي قسم** من لوحة الإدارة، فيظهر تلقائياً في نماذج إضافة وتعديل الخدمة.

**مثال:** قسم الأطباء → حقل «الاختصاص» من نوع قائمة، بـ ٢٠ خياراً لكل منها أيقونة.

### ⚠️ قبل الرفع — مهم جداً

**يجب تشغيل سكربت الترحيل مرة واحدة** بعد رفع الملفات، لإنشاء جداول الحقول:

```
https://t3lam.site/dalel/api/migrate_fields.php
```

افتح هذا الرابط في المتصفح مرة واحدة. سيطبع:
```
✓ جدول category_fields
✓ جدول category_fields_options
✓ نُسخت 20 اختصاصاً كخيارات
```

> **احذف الملف بعد التشغيل** للأمان.

> **لا ترفع** `app.sqlite` أو `secret.key` — الأرشيف لا يحتويهما أصلاً لحماية بياناتك وجلساتك.

## 🧩 أنواع الحقول المدعومة

| النوع | الوصف | مثال |
|---|---|---|
| **قائمة اختيار** | قائمة منسدلة قابلة للبحث، كل خيار بأيقونة | الاختصاص، نوع الوقود |
| **نص قصير** | سطر واحد | اسم الصيدلاني |
| **نص طويل** | عدة أسطر | وصف الخدمة |
| **رقم** | أرقام فقط | سعر المعاينة |
| **نعم / لا** | مفتاح تبديل | يوجد توصيل؟ |

### خيارات إضافية

| الخيار | يظهر لِـ | ماذا يفعل |
|---|---|---|
| **الوحدة** | حقل الرقم | تُلحَق بعد القيمة في العرض: `15,000 ل.س` بدل `15000` |
| **إخفاء عند «لا»** | حقل نعم/لا | لا تُعرض القيمة إطلاقاً إن كانت «لا» — يمنع تكرار شريحة «لا» في كل بطاقة |

> **مثال حقيقي:** «خدمة التوصيل» في الصيدليات مُعلَّمة بـ«إخفاء عند لا».
> من أصل ٢٤٢ صيدلية، ٦٠ فقط عندها توصيل — فبدل أن تحمل ١٨٢ بطاقة شريحة
> «التوصيل: لا» بلا معنى، تظهر الشريحة للستين فقط.
>
> **والفلترة** تعمل مع ذلك: تفعيل «متوفر» يُرجع الستين، لأن غياب الشريحة
> يعني «لا» — وهو التمثيل الصحيح للبيانات.

## 📝 كيف تضيف حقلاً لقسم

1. **لوحة الإدارة ← الأقسام ← تعديل** القسم المطلوب
2. مرّر لأسفل إلى قسم **«الحقول الإضافية»**
3. اضغط **إضافة حقل**
4. املأ:
   - **عنوان الحقل:** الاختصاص
   - **المفتاح (إنجليزي):** `specialty` *(اتركه فارغاً ليُولَّد تلقائياً)*
   - **النوع:** قائمة اختيار
   - **نص إرشادي:** ابحث عن الاختصاص…
5. فعّل الخيارات المناسبة:
   - **إلزامي** — لا يمكن حفظ الخدمة بدونه
   - **يظهر في البطاقة** — يظهر مباشرة في بطاقة الخدمة
   - **قابل للفلترة** — يُضاف شريط فلترة أعلى صفحة القسم تلقائياً
   - **الوحدة** *(للأرقام)* — ل.س · كم · موقف
   - **إخفاء عند «لا»** *(لنعم/لا)* — لا تُعرض القيمة إن كانت «لا»
6. **للقائمة:** اضغط **«خيار إضافي»** لكل خيار:
   - **الأيقونة:** `stethoscope` *(اسم Lucide)*
   - **الاسم:** أمراض قلبية
   - **القيمة:** `cardiology` *(اختياري — يبقى مستقراً لو غيّرت الاسم)*
7. احفظ

## ✨ ما يحدث تلقائياً

بعد تعريف الحقل:

| المكان | النتيجة |
|---|---|
| **نموذج إضافة خدمة** (ويب + أندرويد) | يظهر الحقل تلقائياً حسب القسم المختار |
| **قائمة الاختيار** | بحث سريع + أيقونة لكل خيار |
| **بطاقة الخدمة** | تظهر القيمة كشريحة مع أيقونتها |
| **تفاصيل الخدمة** | تظهر ضمن «معلومات الخدمة» |
| **الخادم** | يتحقق من القيم ويرفض غير الصالحة |

## 🔄 ما نُقل تلقائياً

الاختصصاصات العشرين القديمة **نُقلت** إلى الحقل الجديد:

- ✅ أُنشئ حقل «الاختصاص» لقسم الأطباء
- ✅ نُسخت كل الاختصاصات كخيارات بأيقوناتها
- ✅ الـ ١٥٠ طبيباً الحاليين **يعرضون اختصاصاتهم دون أي تغيير**

**كيف؟** حلّ القيم متسامح مع الصيغتين:
- القيمة = مُعرّف الخيار (الجديد)
- القيمة = نص الخيار (القديم — بيانات ما قبل الترحيل)

في الحالتين يظهر الاختصاص صحيحاً مع أيقونته ✅

## 🐞 خطأ أصلحته أثناء العمل

وجدت أن مسار `DELETE /category-fields/1/options/0` كان يطابق **حذف الحقل** بدل حذف الخيار — فحذف حقلاً حقيقياً بالخطأ.

**السبب:** ترتيب الفحص في الموجّه كان يتحقق من `DELETE /category-fields/{id}` قبل `/options`.

**الحالة:** مُصلح — فحص المسار الفرعي أصبح أولاً.

## 🗂️ بنية قاعدة البيانات

```sql
CREATE TABLE category_fields (
    id            INTEGER PRIMARY KEY,
    category_id   INTEGER REFERENCES categories(id) ON DELETE CASCADE,
    field_key     TEXT NOT NULL,      -- specialty
    label         TEXT NOT NULL,      -- الاختصاص
    type          TEXT DEFAULT 'select',  -- select|text|textarea|number|boolean
    required      INTEGER DEFAULT 0,
    placeholder   TEXT,
    help          TEXT,
    show_in_card  INTEGER DEFAULT 1,
    filterable    INTEGER DEFAULT 0,
    sort_order    INTEGER DEFAULT 0,
    is_active     INTEGER DEFAULT 1,
    suffix        TEXT DEFAULT '',        -- وحدة العرض: ل.س
    hide_when_false INTEGER DEFAULT 0,    -- إخفاء القيمة إن كانت «لا»
    UNIQUE(category_id, field_key)
);

CREATE TABLE category_field_options (
    id         INTEGER PRIMARY KEY,
    field_id   INTEGER REFERENCES category_fields(id) ON DELETE CASCADE,
    label      TEXT NOT NULL,   -- أمراض قلبية
    value      TEXT NOT NULL,   -- cardiology
    icon       TEXT,            -- heart
    sort_order INTEGER DEFAULT 0,
    is_active  INTEGER DEFAULT 1
);
```

**قيم الحقول تُحفظ داخل `services.meta`** بمفتاح الحقل — فلا حاجة لتعديل جدول الخدمات عند إضافة حقول جديدة.

> **الآن `includes/db.php` يُنشئ هذين الجدولين تلقائياً** إن لم يجدا (مع إضافة
> العمودين الجديدين لقاعدة قائمة). سابقاً كانا يُنشآن في `install.php`
> و`migrate_fields.php` فقط — فنشر الكود على قاعدة قديمة أو استعادة نسخة
> احتياطية سابقة كان يُسقط `/api/meta` بخطأ SQL. صار المخطط يُصلح نفسه.

## 🔧 ترحيل النسخة السابقة

إن كانت قاعدتك تعمل بنسخة قديمة من الحقول (حقل «سعر المعاينة» الفارغ في
الصيدليات، خيارات البنزين المتشابكة، مفتاح `f0d00cfdb` في السرفيس):

```bash
php api/migrate_fields_v2.php
```

يأخذ نسخة احتياطية تلقائياً، ويعمل أكثر من مرة بلا ضرر، ولا يحذف أي قيمة
مستخدمين. ما يفعله:

| القسم | التغيير |
|---|---|
| صيدليات | حذف «سعر المعاينة» (صفر بيانات) · إضافة الصيدلاني · دوام ٢٤ ساعة · التوصيل |
| أطباء | إضافة سعر المعاينة (بوحدة ل.س) · المستشفى · إبقاء الاختصاص وخياراته العشرين |
| كازيات | إصلاح بنزين/مازوت المتشابكين وتحويلهما إلى نعم/لا · إضافة الشركة · البطاقة الذكية |
| سرفيس | `f0d00cfdb` ← `direction` مع حفظ خياراته العشرة · نوع المركبة · الأجرة · الانطلاق |
| عام | إصلاح قيم `meta` المشوّهة (`[]` ← `{}`) |

## ❓ ملاحظات

- **المفتاح (key)** يُستخدم للتخزين. لو تركته فارغاً يُولَّد تلقائياً.
- **القيمة (value)** اختيارية — لو تركتها تُستخدم التسمية. الأفضل ضبطها لتظل مستقرة لو غيّرت الاسم لاحقاً.
- حذف حقل **يحذف خياراته تلقائياً** (ON DELETE CASCADE) لكن **لا يحذف قيم الخدمات** المخزّنة في `meta`.
- **«قابل للفلترة» يعمل الآن فعلاً:** كان يُحفظ في قاعدة البيانات ولا يُقرأ في أي
  مكان. صار يُنتج شريط فلترة أعلى صفحة القسم — لأي قسم، بلا تعديل كود.
- **الفلترة لحقول القائمة فقط.** الخيار لا يظهر أصلًا لحقول النص والرقم و«نعم/لا»:
  - النص والرقم: لا معنى لقائمة قيم لا نهائية
  - **نعم/لا: أُلغيت** — كانت تُنتج شريحة «متوفر» لكل حقل (دوام ٢٤ ساعة · التوصيل ·
    بنزين · مازوت) وهي غير مفيدة. هذه الحقول تُعرض في البطاقة فقط.
  - عند تحويل حقل قائمة إلى «نعم/لا» تُلغى فلترته تلقائيًا فلا يبقى إعداد بلا أثر.
- **الفلاتر المفعَّلة حاليًا (٣):** الاختصاص · اتجاه السفر · نوع المركبة
- **التطبيق (أندرويد)** يعرض الحقول والوحدة، ويُخفي «لا» — ويحتاج تحديثاً إلى
  الإصدار ٣ من قاعدة البيانات المحلية (يُرقّي نفسه تلقائياً عند أول تشغيل).
